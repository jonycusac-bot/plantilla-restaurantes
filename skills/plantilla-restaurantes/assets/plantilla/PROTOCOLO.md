# Protocolo por proyecto

1. Leer instrucciones del directorio y respetar el alcance autorizado. Un restaurante, una carpeta, una base y un acceso propios. No tocar otros proyectos ni importar sus datos, fotos, credenciales o configuración. Las instrucciones actuales del usuario prevalecen sobre procedimientos históricos.
2. Antes de modificar una instalación existente, crear respaldo nuevo de código/configuración y .local/ completo. SQLite con API backup o copia con escrituras detenidas de forma autorizada; no copiar solo el archivo de una base activa en WAL. Abrir copia, comprobar integridad, contar platos/fotos, verificar hashes y registrar en BITACORA.md. Respaldos privados fuera de Git/build/generador. Usar una ubicación autorizada, dentro del proyecto si ese es el límite pedido.
3. Conservar carta, identidad, fotos, eventos, traducciones y configuración. Revisar lo existente antes de duplicar funciones. Probar con datos temporales aislados, no con datos del propietario. No borrar imágenes antiguas automáticamente ni reconstruir la base para migrar.
4. Todo local salvo autorización específica. Publicar, crear recursos, consultar cuenta/base remota, cambiar secretos, commit/push y crear repositorios requieren instrucciones expresas. Antes de subir identificar directorio, cuenta y destino nuevo o existente. El usuario debe aprobar un resultado concreto y revisable; no pedir confirmaciones redundantes ya cubiertas por su pedido.
5. No modificar Windows, instalar programas ni detener servicios ajenos sin autorización. No enviar mensajes o publicaciones a terceros sin instrucciones.
6. Registrar cambios, migraciones, respaldos y pruebas reales en BITACORA.md. Crear respaldo final verificado tras intervenciones sobre datos/código existente. Informar pendientes y distinguir build/exportación de publicación.
